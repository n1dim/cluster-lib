# cluster

Библиотека на C для организации распределённых вычислений на нескольких узлах сети.
Реализована в рамках практикума «Вычислительный кластер» 

В качестве демонстрации библиотека используется для численного расчёта интеграла
`∫₀¹ 4/(1+x²)dx = π` методом средних прямоугольников с адаптивным уточнением точности.

## Архитектура

Библиотека предоставляет два интерфейса, определённых в [`include/cluster.h`](include/cluster.h):

- **`ClusterWorker`** («рабочий узел») — предоставляет часть вычислительных ресурсов
  машины управляющему узлу. Задаётся максимальным числом ядер и тайм-аутом ожидания.
- **`ClusterControl`** («управляющий узел») — разбивает задачу на подзадачи,
  распределяет их между рабочими узлами, собирает и объединяет результаты, печатает
  итог в stdout. Задаётся минимальным числом требуемых рабочих узлов и тайм-аутом
  всего вычисления.

Прикладной код реализует два коллбэка:

- `cluster_subtask_fn_t` — вычисление подзадачи на рабочем узле (получает индекс
  воркера, их общее число и текущее количество шагов дискретизации);
- `cluster_combine_fn_t` — объединение частичных результатов, полученных от всех
  воркеров, в итоговое значение (на стороне управляющего узла).

### Протокол обмена

Узлы обмениваются сообщениями по TCP (`src/protocol.h`): `MSG_TASK` (control → worker),
`MSG_RESULT` (worker → control), `MSG_ABORT` и `MSG_DONE`. Управляющий узел итеративно
удваивает число шагов дискретизации `n`, пока разница результата между двумя
последовательными итерациями не станет меньше заданного `epsilon`.

### Параллелизм и отказоустойчивость

- Внутри каждого рабочего узла подзадача дополнительно распараллеливается по ядрам
  через пул потоков (pthreads) — так суммарное время вычисления обратно
  пропорционально общему числу задействованных ядер сети.
- Соединения настраиваются через `SO_KEEPALIVE`/`SO_RCVTIMEO`/`SO_SNDTIMEO`
  (`src/net_utils.h`); разрывы соединения и тайм-ауты обнаруживаются через `poll()`
  и коды возврата `read()`/`write()`.
- При отказе любого узла или сети управляющий узел рассылает `MSG_ABORT` всем рабочим
  узлам и завершает работу с ошибкой; аналогично рабочий узел, обнаруживший сбой,
  посылает `MSG_ABORT` перед выходом.

## Сборка

```sh
make            # собрать библиотеку libcluster.a и примеры worker_app / control_app
make clean      # удалить артефакты сборки
```

Дополнительные цели:

| Команда         | Назначение |
|-----------------|------------|
| `make all-gcc`   | сборка примеров компилятором gcc с флагами безопасности (`-fstack-protector-strong`, `_FORTIFY_SOURCE=2`, `-fPIE`, `relro`/`now` и др.) |
| `make all-clang` | то же самое компилятором clang |
| `make analyze`   | статический анализ через `scan-build` (clang static analyzer), нулевые предупреждения |
| `make docs`      | сборка документации API через Doxygen (`Doxyfile`) в каталог `docs/` |
| `make test`      | запуск сценариев `test.sh` (см. ниже) |
| `make run`       | быстрая демонстрация на одной машине: 2 воркера + управляющий узел |
| `make bench`     | бенчмарк масштабируемости: 1 воркер с 1/2/4/8 ядрами |

## Запуск примера

Рабочий узел:

```sh
./worker_app <port> <max_cores> <timeout_sec>
```

Управляющий узел:

```sh
./control_app <num_workers_required> <timeout_sec> host:port [host:port ...] [n0]
```

Пример на одной машине (2 узла по 2 ядра):

```sh
./worker_app 9001 2 60 &
./worker_app 9002 2 60 &
./control_app 2 60 127.0.0.1:9001 127.0.0.1:9002
```

Вывод содержит вычисленное значение интеграла, эталонное значение π, абсолютную
погрешность и время вычисления.

## Тесты

`test.sh` (запускается через `make test`) прогоняет на локальной машине:

1. вычисление с двумя воркерами;
2. вычисление с одним воркером на 4 ядрах;
3. вычисление с четырьмя воркерами по одному ядру;
4. отсутствие доступных воркеров (ожидается код ошибки);
5. сравнение времени 1×1 ядро vs 2×2 ядра (масштабируемость);
6. отключение воркера во время вычисления (обнаружение отказа управляющим узлом);
7. отключение управляющего узла во время вычисления (обнаружение отказа воркером);
8. тайм-аут воркера при отсутствии подключения от управляющего узла.


## Структура репозитория

```
include/cluster.h        — публичный API (ClusterWorker, ClusterControl)
src/worker_node.c        — реализация рабочего узла (пул потоков, приём задач)
src/control_node.c       — реализация управляющего узла (распределение, сбор результатов)
src/protocol.h           — формат сообщений TCP-протокола
src/net_utils.h          — вспомогательные функции сокетов (send_all/recv_all, тайм-ауты)
examples/worker_app.c    — пример рабочего узла (подынтегральная функция)
examples/control_app.c   — пример управляющего узла (суммирование частичных результатов)
test.sh                  — набор тестовых сценариев
Doxyfile                 — конфигурация Doxygen
Makefile                 — сборка, тесты, анализ, документация, бенчмарк
```
